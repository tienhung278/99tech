# Provider adapters verify and normalize callbacks

Each PSP has its own signatures, amount units, and status vocabulary. The configured callback route identifies the provider without trusting a payload field, preserves raw request bytes for signature verification, and passes them to that provider's adapter. The adapter verifies and normalizes the request into a canonical event before the provider-independent settlement service sees it. The mock provider's currency is set in configuration; providers that supply a currency must match it, and settlement performs no conversion. This keeps the money-moving state machine shared across providers while allowing a new integration to consist mostly of an adapter, configuration, and sanitized provider fixtures. Fixture tests cover valid and invalid signatures, each status and amount format, and a shared settlement contract with a fake provider. Placing provider checks in the route or settlement service would make each new PSP change shared payment logic.

The provider registry maps provider ID to adapter, expected currency, signature secret reference, and status mapping. It validates required configuration at startup, and secret values stay outside source control.
